🖥️ Vibe Coding Setup Guide

Everything on this page assumes you've never opened a terminal before. By the end, you'll have Node.js, Git, VS Code, and (optionally) Claude Code running on your own machine — the same tools used in the talk.

WHAT YOU'LL HAVE WORKING BY THE END

  • A terminal that understands node -v and npm -v
  • Git installed, so git push actually works
  • VS Code, so you can see and edit the files Claude writes
  • (Optional) Claude Code, so Claude can run those commands for you
  • Your own project, pushed to GitHub and live on a Vercel URL
1

Install Node.js & npm

Next.js — and the app you'll build — runs on Node. npm (Node's package manager) comes bundled with it.

  1. Go to nodejs.org and download the button labeled LTS.
  2. Open the downloaded .pkg file and click through the installer (defaults are fine).
  3. Open the Terminal app (search for it with Spotlight — Cmd + Space, type "Terminal").
  4. Check it worked:
  1. Go to nodejs.org and download the button labeled LTS.
  2. Run the downloaded .msi installer. Keep clicking Next — leave "Add to PATH" checked (it's on by default).
  3. Open PowerShell (search for it in the Start menu).
  4. Check it worked:
node -v
npm -v

Both should print a version number (like v22.11.0). If you instead see "command not found," close the terminal completely and reopen it — installers set your PATH, but windows already open don't see the update.

2

Install Git

Git is the tool that actually does git push — separate from having a GitHub account.

  1. Open Terminal and type:
git --version

If it's not already installed, macOS will pop up a prompt to install the "Xcode Command Line Tools." Click Install and wait a few minutes — that installs Git along with it.

  1. Go to git-scm.com, download, and run the Windows installer.
  2. Keep the default options — this also installs Git Bash, a terminal you can use instead of PowerShell if you prefer.
  3. Verify in PowerShell or Git Bash:
git --version
3

Set up GitHub authentication

GitHub no longer accepts your account password for git push — you need a token instead.

  1. On github.com, click your profile photo → Settings → Developer settings → Personal access tokens → Tokens (classic).
  2. Generate a new token, check the repo scope, and copy the token somewhere safe — GitHub only shows it once.
  3. The first time you git push from a new machine, it'll prompt for a username and password. Enter your GitHub username, then paste the token as the password.
Shortcut: installing the GitHub CLI and running gh auth login sets this up automatically, no token-copying required.
4

Install VS Code

This is where you'll actually see the files Claude writes, and where you'll run the terminal commands above going forward.

  1. Download from code.visualstudio.com — it's a .zip.
  2. Unzip it and drag Visual Studio Code into your Applications folder.
  3. Open it, then open the built-in terminal with Cmd + \` (backtick, top-left of your keyboard).
  1. Download from code.visualstudio.com — the "Windows" button.
  2. Run the installer; leave "Add to PATH" checked.
  3. Open it, then open the built-in terminal with Ctrl + \` (backtick).

From here on, do everything — npm install, git push, running Claude Code — from this built-in terminal, so it's always in the right project folder.

5

Install Claude Code optional

Lets Claude create files, run npm install, and push to GitHub directly — instead of you copy-pasting code out of a chat window by hand.

In the VS Code terminal:

npm install -g @anthropic-ai/claude-code

Then start it and log in with your Claude account:

claude
6

Final check

Run all of these in one go — every line should print a version number.

node -v
npm -v
git --version
code --version
claude --version

Skip the last line if you didn't install Claude Code. If everything prints a version, you're ready to build.

7

Create your project folder

Everything Claude writes needs to land somewhere specific on your computer — this is that folder.

  1. Pick a spot (like your Desktop) and open a terminal there — in VS Code, use File → Open Folder to open that spot first, then use its built-in terminal.
  2. Create and enter a folder for the project:
mkdir hbs-pac-man
cd hbs-pac-man

Now hand this folder to Claude. If you're using Claude Code, run claude right here and paste the sample prompt — every file it creates lands in this folder. If you're pasting code from claude.ai chat instead, save each file it gives you into this same folder, matching the file paths it names (e.g. app/page.tsx).

Once the files exist, install dependencies and preview it:

npm install
npm run dev

Open localhost:3000 in your browser — that's your app, running only on your machine so far.

8

Build it in 5 stages

One big prompt asking for the whole game at once is slow and unreliable — it can easily run 20+ minutes and still come out broken. Ask for one feature at a time instead: each stage below should take a few minutes, and you can see and test each one before moving to the next.

First, initialize git in this folder so you can commit after each working stage — that gives you an easy undo if a later stage breaks something:

git init

Stage 1 — Maze + movement (~5 min)

Create a Next.js (App Router) app called "HBS Pac-Man." On the home
page, add a client component with an HTML5 canvas showing a simple
fixed maze (walls and open paths) and a small circle representing
the player. The player moves through the open paths using the arrow
keys and can't pass through walls. No ghost, no dots, no scoring yet
— just the maze and movement.

Before writing code, ask me 2-3 questions about maze size or player
speed.

Test it at localhost:3000, then commit: git add . && git commit -m "stage 1: maze + movement"

Stage 2 — Dots + score (~4 min)

Add small dots scattered across the open paths of the maze. When the
player's circle overlaps a dot, remove that dot and increase a score
counter shown on screen.

Test, then commit: git add . && git commit -m "stage 2: dots + score"

Stage 3 — Ghost + game over (~5 min)

Add one ghost, drawn as a different colored circle, that moves along
a fixed patrol route or randomly through the open paths — it should
not chase the player. If the ghost touches the player, stop the game
and show a "Game Over" overlay with the final score and a Play Again
button.

Test, then commit: git add . && git commit -m "stage 3: ghost + game over"

Running short on time? Stages 1–3 already give you a complete, playable game. Treat stages 4–5 below as a stretch goal, or come back to them later.

Stage 4 — Save the score (~6 min)

On the Game Over overlay, add a text input for the player's name and
a Submit button. On submit, save the name, score, and current time to
a Supabase table called leaderboard (columns: name text, score int,
created_at timestamp) using @supabase/supabase-js.

Test, then commit: git add . && git commit -m "stage 4: save score to supabase"

Stage 5 — Live leaderboard (~4 min)

Below the game, show a live top-10 leaderboard pulled from the
leaderboard table, sorted by score descending. Refresh it
automatically after a new score is saved.

Test, then commit: git add . && git commit -m "stage 5: live leaderboard"

9

Push it to GitHub

Vercel deploys from a GitHub repo, not from your laptop directly — this step gets your code up there.

If you committed after each stage above, your work is already saved locally — skip ahead to creating the repo. If not, commit everything now:

git add .
git commit -m "Initial commit"
  1. Go to github.com/new. Name the repo (e.g. hbs-pac-man), keep it empty — don't check "Add a README" or ".gitignore," since your folder already has files.
  2. After creating it, GitHub shows you commands under "…or push an existing repository." They'll look like this — use the ones it actually shows you, since the URL is specific to your repo:
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/hbs-pac-man.git
git push -u origin main

This is the push that'll prompt for the personal access token from Step 3. Refresh the GitHub repo page afterward — your files should be there.

10

Deploy on Vercel

This turns the GitHub repo into a live, public URL.

  1. Go to vercel.com/new and sign in with GitHub if it asks — this lets Vercel see your repos.
  2. Find your repo in the list and click Import.
  3. Vercel auto-detects Next.js — you don't need to change any build settings. Click Deploy.
  4. If your app uses Supabase, add your Supabase URL and anon key first: in the project's Settings → Environment Variables, add them, then redeploy so the app can actually reach the database.

A minute or two later, you'll have a live your-project.vercel.app URL. Every future git push to main redeploys it automatically.

11

Troubleshooting

"node" or "npm" is not recognized / command not found

Fully quit and reopen your terminal (or restart your computer). The installer updates your PATH, but a terminal window you already had open won't see the change.

PowerShell won't run npm — "running scripts is disabled"

Open PowerShell as Administrator once and run Set-ExecutionPolicy RemoteSigned, then type Y to confirm. Or just use Git Bash instead of PowerShell — it doesn't have this restriction.

"permission denied" (EACCES) installing global npm packages

Don't use sudo — it causes more problems later. This usually means Node was installed in a way that needs admin rights for global installs; reinstalling Node from the official nodejs.org installer (not Homebrew) usually fixes it.

git push asks for a password and then rejects it

GitHub disabled plain password auth for git operations. Use a personal access token as the password (Step 3), or set up the GitHub CLI with gh auth login.

"code" command doesn't work in Terminal

Open VS Code, press Cmd+Shift+P, type "Shell Command," and choose Install 'code' command in PATH.

Vercel deploy succeeds but the leaderboard / database doesn't work

Almost always missing environment variables. Double-check Settings → Environment Variables has your Supabase URL and anon key, then trigger a new deploy — variables only apply to deploys made after you add them.
